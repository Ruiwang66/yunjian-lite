# v0.5.0 升级与回滚

日期：2026-11-04。本文按升级方案编写；截至该日尚未操作生产服务器、提交、推送或创建 Release。2026-11-06 已另行完成一次 v0.5 生产部署；本文仍是通用升级与回滚步骤，不替代实际部署记录。

## 配置与数据

- **没有新增环境变量、角色、入站端口或管理能力。** 沿用现有 `PUBLIC_URL`、`COOKIE_SECURE`、`TRUSTED_PROXY_CIDRS`、`ALLOW_LEGACY_REPORTS` 及 Agent 参数。
- 不改数据库字段，不删除表；原有 AutoMigrate 仍可重复执行。用户、密码哈希、会话、节点密钥、地区、历史、网站、备份记录和安全规则保留。
- `METRIC_RETENTION_DAYS` 保留用户设置，默认 30 天、允许 1–365 天。指标和系统事件按服务端 UTC、连续 24 小时计算，严格早于截止时刻才清理；恰好截止时刻的记录保留。
- 操作审计仍为 90 天；任务结果 5 分钟、任务记录 1 天；安全数据仍按每台服务器原有配置，未配置时 90 天。不可把这些全部改成 30 天。
- 前台保留期说明文字沿用默认 30 天；实际清理以环境配置为准，本次没有增加公开配置接口。

## 构建要求

- 最低 **Go 1.27.3**，`go.mod` 和 Docker 构建镜像已更新。旧二进制不会因为更新源码而自动获得标准库修复，需要重新构建并替换程序。
- Docker 前端构建采用 **Node 24.22.2 LTS**，覆盖 2026-10 官方安全更新。Node 不进入 scratch 运行镜像。保持 npm 和现有锁文件；`npm ci --ignore-scripts` 已通过本地生产构建验证。
- `x/net` 0.58.0 → 0.62.0；依赖约束同时要求 `x/crypto` 0.58.0、`x/sys` 0.49.0、`x/text` 0.43.0。保留 bcrypt 和会话体系，未更新其他主框架。
- Windows `scripts/build.ps1` 优先使用项目内 Go，以及存在时的 `.tools/node/node-v24.22.2-win-x64/npm.cmd`，否则使用系统 npm。没有全局安装工具链。

## 建议顺序

1. 记录当前程序/镜像版本、完整配置、卷名和 Agent 参数。备份完整数据目录与受保护配置，限制备份权限。
2. SQLite 已使用 WAL。可停服务后备份完整数据目录；不停机时须使用 SQLite 一致快照/备份机制。**不能仅复制运行中的主 `.db` 文件而遗漏 WAL。** 本次在隔离测试中验证了网站 SQLite 备份能包含尚未 checkpoint 的 WAL 内容，未备份真实生产数据。
3. 在隔离环境运行 Go test/vet、前端测试/构建和目标平台验证，检查本文与验证报告中的未测项。Docker 镜像需在有 Docker 的目标环境实际构建和启动。
4. 先更新 Server，保留原持久化卷、配置、运行 UID 与文件权限；不要重新初始化账户或换成空数据目录。检查健康、登录、地图、旧 Agent 上报和各已有页面。
5. 按主机逐台更新 Agent。原有 v0.2–v0.4 协议仍是 management/website/security 各 1，不需要轮换密钥。新 Agent 仍能协商旧控制端，缺少协议字段时不发送新扩展。
6. Linux 管理/安全检测仅保留原授权；监控专用、Windows 和容器监控兼容模式不增加能力。NAT 继续主动出站，不需要公网 IP、监听端口、端口映射、privileged 或额外 capabilities。

更新 Agent 才能获得其内嵌标准库修复、扩展协商合并和结果重试修复；旧 Agent 可继续监控，但不应长期使用旧工具链构建的程序。

## 需知的行为收紧

| 行为 | v0.5 | 对正常使用的影响 |
| --- | --- | --- |
| 登录与密码重置并发 | 签发会话时事务复核密码/角色 | 重置期间使用旧密码的请求返回 401，请用新密码登录 |
| 首次管理员创建/CLI 重置 | 数据目录内独占 `.admin-initialization.lock` | 防止两个进程改坏密码文件；不允许并发初始化/重置 |
| 会话或能力撤销 | 不再签发对应任务；回传再次复核并拒绝缓存 | 已在远端执行的动作不能撤回；取消/超时须先核对实际状态，不能据此重复执行 |
| WebSocket | 私有推送前复核；公开通道只保留监控变化 | 当前浏览器退出会关闭连接；其他空闲连接最迟 25 秒心跳关闭，已在途的数据不能撤回 |
| 认证 JSON | 登录/密码/用户入口 2 KiB | 合法账号/密码在原字节限制内可容纳；其余报告/结果/上传仍为 64 KiB HTTP JSON 及原类型限制 |
| 限流 | 匿名来源、账户与节点独立预算 | 匿名/登录来源 5/s、突发 60；私有和 Agent 各来源入口 128/s、突发 512，认证后各账户/节点 5/s、突发 60；429 带重试指示 |
| WebSocket 数量 | 全局 256；公开每来源 8，私有每账户 8 | 同 NAT 的不同已登录账户不再共用匿名连接额度，超限仍可使用原 4 秒轮询 |
| 发布包下载 | 全局最多 16 个传输，每个最多 5 分钟 | 超并发返回 503 / Retry-After: 5；大批安装请错峰重试；短 JSON 和 WS 不使用这个长期限 |
| 网站检查时间 | 拒绝非正/超前 5 分钟的时间，缓存以接收 UTC 保存 | 原正常 v0.3/v0.4 Agent 无需改协议；旧缓存中异常远期时间可被下一次合法检查纠正 |
| 网站出站地址 | 补充拒绝旧 IPv6 站点本地、兼容/转换等特殊地址 | 延续既有公网域名检查策略，不新增内部网站探测；NAT 监控和既有主机本地操作不受此限制 |
| TLS/依赖修复 | 沿用可信证书链与主机名验证 | 若旧部署依赖已不可信的证书链，应修复证书，不应跳过校验或降级无认证 |

首次初始化或 CLI 重置异常退出可能留下锁。确认没有初始化/重置进程正在运行后，才由主机管理员处理**该数据目录中的这一个锁文件**；不要删除密码、数据库或整个数据目录。已有管理员的普通启动不会重置密码。

HTTPS 反代请保留 Host，明确配置代理实际源 CIDR，继续使用 HTTPS `PUBLIC_URL`。不要信任任意 `X-Forwarded-For` / `X-Real-IP` / `X-Forwarded-Proto`。示例超时见 [安装说明](INSTALL.md)；本次未改动任何实际 Nginx、防火墙、SSH 或云规则。

## 回滚限制

- 本次没有破坏性数据迁移，可换回旧 Server/Agent 程序和模板配置；**保留当前数据卷和最新数据库，不能用旧备份覆盖升级后产生的新数据。** 停机备份仍是回滚前提。
- 回退代码会重新引入本次修复的授权、会话、网络解析与稳定性问题。不要为回滚关闭 Secure、来源验证、TLS 或主机白名单。
- 本地修改前的 287 个工作文件、哈希和原暂存/未暂存差异在忽略目录 `.runtime/v05-baseline/`。这不是运行数据库备份；原 Git 索引包含用户的 v0.4 改动，不能用 HEAD/v0.3 或 `git reset --hard` 代替基线。恢复前应逐文件核对，保留此后新增的用户修改。
- 新的测试数据库、回环预览、便携工具和截图仅在忽略目录中，不应放入发布包或生产数据卷。

验证范围见 [测试报告](V0.5-VERIFICATION.md)，问题证据和剩余边界见 [审查报告](V0.5-SECURITY-AUDIT.md)。
