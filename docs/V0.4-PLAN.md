# v0.4 初始开发计划与审查（历史记录）

2026-10-19 初始计划。当时的范围仅为本地开发、测试和预览；后续经授权完成云端部署及源码发布。当前使用方法见 [V0.4.md](V0.4.md)，分阶段验证边界见 [V0.4-VERIFICATION.md](V0.4-VERIFICATION.md)。

## 阶段 1：已核对的 v0.3 架构

- 本地 Git 初始提交早于公开 main，发布必须以公开 main 的最新提交为父提交，不能覆盖公开历史。v0.3 源码备份保留在本地，不进入公开归档。
- Gin + GORM/SQLite 增量迁移；会话、Origin/Host、RBAC、审计与 WebSocket 已存在。admin/operator/viewer 共享同一工作区，不是租户隔离。
- 客户端每 4 秒主动上报，通过认证的 operations/next/result 领取唯一任务和租约；同机一次执行一个任务，结果重试不重跑，任务校验服务器、密钥、会话与期限。
- Linux 运维需明确启用；Windows 仅监控。容器兼容模式与运维互斥，保留普通账户、空能力集及 128 MiB 限制。
- 网站依赖 root 本地白名单，标准 Nginx 目录；证书只读，备份手动。v0.3 无证书签发或自动备份调度。
- 现有离线地图、公开地区投影、登录、导航及命令框隐藏滚动条应保留。安全数据不进入公开接口或地图。
- 指标/事件默认 30 天，操作审计 90 天；已有测试覆盖角色、重放、跨服务器租约、网站、文件、迁移、地图及兼容安装。
- Docker 运行时非 root、只读文件系统、无 socket；安全检测仍由目标主机发起的任务通道执行，不增加入站端口。

## 阶段 2–8 实施顺序

1. 增加结构化只读检查、明确状态、加权评分、六类安全实体和增量迁移。未知/失败/未安装均不算通过，人工状态不改变评分。
2. Linux 显式 `--management --security` 才能执行 security.scan；本地配置授权日志，沿用网站白名单、Docker 工具与固定参数。普通/容器模式不增加能力。
3. 复用持久化任务与租约，增加扫描、明细、规则、历史、告警、报告和按权限控制的定时扫描；限制时间、并发、结果大小及保留期。
4. 新增黑白安全中心页面；保留原命令页面和导航视觉，提供服务器/风险/时间筛选、评分/事件趋势、报告及告警。
5. 添加真实规则与日志夹具、API 权限和任务隔离测试，全量回归与构建；在独立本地数据库启动预览。模拟数据须明确标注，不能冒充 Linux 真机检测。
6. 更新 README、CHANGELOG、版本、使用指南、验证记录与限制。用户本地确认后，另行授权发布/部署。

## 验证原则

Windows 上无法执行的 Linux root/Nginx/firewall 真机检查应明确列出；使用固定工具夹具测试规则与通道，并以本机真实可读取数据验证采集限制。不得宣称未经实测的低资源性能指标，不扫描外部资产或试停业务服务。
