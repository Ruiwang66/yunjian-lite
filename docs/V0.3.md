# 云简 Lite v0.3 网站与应用管理

v0.3 在 v0.2 上新增网站登记、Nginx 管理、SSL 检测、域名监控、PHP 环境检测、网站健康检查和手动备份。原监控、4 秒采集、30 天指标与事件保留、三种角色和 90 天运维审计继续保留。

## 本地测试

`scripts/local-v03-preview.go` 是独立的本地测试入口：使用真实 API、SQLite、角色和任务流程，Linux 环境、访问检测与 Nginx 操作为明确标注的模拟数据；手动备份写入独立测试目录。它不进入生产服务端或 Docker 镜像。

```powershell
go run -tags nomsgpack ./scripts/local-v03-preview.go
```

打开 `http://127.0.0.1:5053/login`。测试账号 `admin`、`operator`、`viewer`，密码均为 `CloudEase03!Test`，仅适用于本地夹具。数据库位于 `.runtime/v03-preview/data`，与原部署数据库分开。

## 升级与授权

先停止旧服务并备份完整 SQLite 数据目录、配置及旧程序。新服务端通过 AutoMigrate 新增 `websites`、`ssl_certificates`、`domains`、`backup_tasks`、`health_checks` 及任务的网站关联，不删除原用户、会话、服务器、密钥、指标和事件。保留原 Compose 项目名与数据卷，不使用 `down -v`。

升级服务端、前端和下载目录中的客户端程序。v0.3 客户端通过认证的 `website_protocol=1` 协商后才发送网站字段；连接 v0.1/v0.2 服务端时保留原监控协议。v0.1/v0.2 客户端可继续向新版上报监控，但不会获得网站管理能力。

网站管理需要 Linux root 客户端已启用 `--management`，再配置 **主机本地**网站白名单。网页只能登记与操作已经授权的站点，不接受任意目录、Nginx 配置文本或数据库凭据。仅升级控制台不会自动授予权限。

## 主机配置

本版站点启停支持 Debian/Ubuntu 常用的 `/etc/nginx/sites-available` 和 `/etc/nginx/sites-enabled` 布局。宝塔等不同 Nginx 布局不能直接套用启停操作；不要将其业务配置搬移或放宽目录来绕过检查。

准备已存在的网站目录、站点配置和私有备份目录。以下示例目录及父目录须为 root 所有，禁止组/其他用户写入和符号链接；站点配置须为 root 所有的普通文件，不接受共享硬链接。

```bash
install -d -m 0755 /srv/cloud-sites/blog
install -d -m 0700 /var/backups/cloud-ease
install -d -m 0750 /etc/cloudease-lite
```

将 `/etc/cloudease-lite/websites.json` 设置为 root 所有、`0600`，内容示例：

```json
{
  "nginx_available_dir": "/etc/nginx/sites-available",
  "nginx_enabled_dir": "/etc/nginx/sites-enabled",
  "backup_dir": "/var/backups/cloud-ease",
  "sites": [
    {
      "name": "我的博客",
      "domain": "blog.example.com",
      "root_path": "/srv/cloud-sites/blog",
      "nginx_config": "blog.conf"
    }
  ]
}
```

最多授权 20 个站点；域名仅允许规范小写 DNS 名称，配置文件只允许单个安全文件名。配置及备份目录不能放在网站根目录内。

在 `/etc/cloudease-lite/agent.env` 加入 `CLOUDEASE_WEBSITE_CONFIG=/etc/cloudease-lite/websites.json`，或手工启动客户端时传入 `--website-config`。Linux 自动安装选择运维模式时，会保留对上述标准白名单文件的引用。首次配置还需 `systemctl edit cloud-agent`，仅为写入目录放行：

```ini
[Service]
ReadWritePaths=/etc/nginx/sites-enabled /var/backups/cloud-ease
```

如采用其他私有备份目录，应在此明确添加该目录。然后执行 `systemctl daemon-reload` 与 `systemctl restart cloud-agent`。客户端会校验 JSON、目录和文件权限，不安全时拒绝启动网站功能。配置应由主机管理员维护，网页不能修改白名单。

## 网站管理教程

1. 在「网站管理」选择已连接的 v0.3 Linux 服务器。
2. 点击「添加网站」，从客户端白名单选择域名，填写显示名称；目录和配置文件只读。
3. 「查看」展示健康状态、A/AAAA、响应时间、证书与检测时间；「编辑」修改登记信息；「检测」执行一次即时检查。
4. 查看弹窗的 Nginx 标签可以读取配置、启用和禁用现有站点。启停会先写入私有配置备份、执行固定 `nginx -t`，通过后固定重载 `nginx.service`；失败恢复原启用链接。配置检查失败不会继续重载。仅操作本白名单对应的链接，不覆盖其他文件。
5. 删除只删除控制台登记与检测缓存，不删除主机文件、Nginx 配置或已有备份。运行中的操作可能已经执行，删除记录不能撤回，应先等待完成。

本版网站创建是 **登记现有站点**，不自动部署应用、生成业务代码或写入任意 Nginx 配置。

## SSL 与域名

在「SSL 证书」页面查看机构、有效期、剩余天数、TLS 版本和证书链。30 天内到期提醒，7 天内高危。支持检测 443 和 HTTPS，不申请、签发、上传私钥或自动续期。证书异常时不跳过校验访问页面。

客户端约每 30 秒在后台轮转刷新授权站点检测，不阻塞 4 秒基础采集；单轮有时间预算，保留各站点最近结果，站点较多时可主动检测未刷新的站点。增强列表超过上报大小限制时会省略大列表，基础监控继续上报。DNS 的 A/AAAA 地址必须均为公网地址；解析后固定连接目标，禁止访问本机、内网、链路本地、云元数据地址和保留地址。不使用环境代理，不跟随 HTTP 重定向。HTTPS 失败时可读取同一已验证目标的 HTTP HEAD 状态，但不会把 HTTP 可达当成 HTTPS 正常。

网站页面展示 HTTP 状态码、响应时间、可访问性、TLS 错误、502/504 等异常。根目录权限和 `.env`、`.git`、backup/backups 风险仅在本机检查存在性，不读取其内容，不请求公网敏感路径；是否暴露仍需核对 Nginx 拒绝规则。

### 已有证书的 HTTPS 配置示例

在目标 Linux 主机准备已签发且与域名匹配的证书，将下方示例合并到白名单对应的现有站点配置。使用自己的域名、目录和证书路径；证书私钥只在主机保存，不上传控制台。更改之前备份原配置，不覆盖其他业务的 server 块。

```nginx
server {
    listen 443 ssl;
    server_name blog.example.com;
    root /srv/cloud-sites/blog;
    index index.html;
    ssl_certificate /etc/letsencrypt/live/blog.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/blog.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    autoindex off;
    location ~ /\.(env|git)(/|$) { deny all; }
    location ~ ^/(backup|backups)(/|$) { deny all; }
}
```

先在主机执行 `nginx -t`，通过后再重载 Nginx。确保 DNS 指向正确公网地址、443 可达且私钥读取权限适合已有 Nginx 部署，再在 SSL 页面点击检测。云简 v0.3 不负责证书签发与续期。

## PHP 环境检测

检测 PHP CLI 版本、FPM 服务状态以及 curl/gd/mysqli/pdo/openssl 扩展。对 expose_php、display_errors、disable_functions 给出静态提示。CLI 与 FPM 可能使用不同配置，检测结果不能代替 FPM 配置审计；不自动安装扩展、升级 PHP 或修改 php.ini。

## 手动备份

网站卡片「管理」菜单支持文件和数据库备份；名称、大小、时间、状态和 SHA-256 存入备份记录。操作仅由 admin/operator 手动触发；`GET /api/backup/schedule` 返回 `enabled=false`，保留将来自动备份的接口，当前不会定时备份。

- 文件备份为 ZIP，最多 10000 个文件、256 MiB 原始文件总量，拒绝链接和特殊文件，排除 `.git`、backup/backups、node_modules；应用运行中写入的文件发生变化会中止，静态文件备份不能保证跨文件事务一致性。
- SQLite 在白名单中加入 `sqlite_path`，使用只读连接的 `VACUUM INTO` 生成一致快照。源数据库须为 root 所有的普通文件，父目录安全，不允许共享硬链接。
- MySQL/MariaDB 在白名单中加入 `mysql_database` 与 `mysql_defaults_file`。数据库名只允许字母、数字、下划线；本地私有 defaults 文件最多 512 字节，包含 `[client]` 的 socket/user/password，网页不接收或返回密码。使用固定 mysqldump/mariadb-dump 参数和 `--single-transaction`，事务一致性针对 InnoDB；其他引擎应在主机安排合适停写策略。
- 每次最多 90 秒、256 MiB；每个备份目录最多 200 项 / 2 GiB，达到限制后拒绝新增，管理员在主机手动清理。数据库源变化和输出限制导致失败时不保留半成品。
- 备份目录为 root 专用 `0700`、备份文件 `0600`，位于目标主机，不提供公开下载或一键恢复；数据库和 `.env` 可能包含凭据，恢复和异地存储由主机管理员操作。

## 权限和验证边界

admin/operator 可登记、编辑、删除和执行主动检查、站点启停、备份；viewer 只读，可查看已保存信息和 Nginx 配置。所有新 API 要求会话并记录审计。普通任务 45 秒过期，备份 120 秒过期，不自动重试；超时不代表未执行。

测试覆盖迁移保留、三种角色、主机白名单、结果绑定、审计、ZIP、SQLite 快照、取消和拒绝危险网络地址。Windows 本地夹具与交叉编译不代替 Linux 真机的权限/systemd/实际 Nginx 重载及 MySQL 一致性验收。具体结果见 [v0.3 验证记录](V0.3-VERIFICATION.md)。
