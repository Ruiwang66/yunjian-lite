# 云简 Lite v0.4 安全中心

v0.4 在现有 v0.3 增加可选的只读安全中心。没有自动修复、漏洞利用、任意目标扫描、自动封禁或远程 shell。本指南适用于 v0.4 源码；生产控制端使用正常的 server 程序，下方测试夹具仅供独立本地验证，不能作为生产入口。

## 本地测试

本地预览使用独立数据库 `.runtime/v04-preview/data`，与 v0.3 数据和生产数据分开。

- 地址：`http://127.0.0.1:5054/security-center`。
- 本地夹具账号：admin、operator、viewer；密码 `CloudEase04!Test`。仅用于本地测试，不能用于生产。
- admin/operator 可进入安全中心；viewer 不显示入口，API 也拒绝读取与执行安全检测，原有只读监控权限保留。
- 名称带“Linux 检测输入模拟”的服务器、页面黄色提示和报告范围均明确标识模拟输入。它运行真实的 API、持久化任务、租约、规则、评分及告警流程；Linux/SSH/证书输入不是本机真实观测。
- 点击“开始只读检测”，等待客户端领取任务。每台服务器最少间隔 1 分钟；重复检测不反复通知持续存在的同一高风险。
- 检查风险明细、误报标记、站内告警已读状态、JSON 报告、时间/风险筛选和评分变化。手动标记不会删除证据或改变分数。
- 原有命令页面仍在 `/security`，新增安全中心为 `/security-center`；地图、登录和前台不重新设计。

可手动启动测试夹具（仅回环监听）：

```powershell
go run -tags nomsgpack ./scripts/local-v03-preview.go --security-demo --root .runtime/v04-preview --listen 127.0.0.1:5054
```

也可自行构建上述测试脚本，启动时将 `--root` 与 `--web` 指向独立测试目录及前端构建目录。演示程序不进入生产 Docker 镜像或正式服务端。

## Linux 客户端启用

安全检测默认关闭，需要 v0.4 Linux 客户端同时显式启用 `--management --security`。安装弹窗先勾选“启用运维管理”，再勾选“启用 v0.4 只读安全检测”；执行安装命令并在隐藏提示输入该机器的连接密钥。已有安装应先备份服务与本地配置，复用原密钥，不必轮换。

仅升级控制台或客户端不会开启安全检测；旧客户端继续监控。v0.4 与旧控制台协商不支持安全协议时，不在上报中发送新能力字段。

安全中心右上角提供“开启安全检测”按钮；已开启时显示“检测配置”。点击后可查看当前服务器的启用步骤并复制命令，在对应 Linux 主机用 root 执行。命令仅适用于已运行且已授权 root 运维管理的 v0.4 客户端：复用原密钥和启动参数，备份原配置，通过独立 systemd drop-in 添加 `--security` 并重启客户端；失败时撤销本次新增配置。它不会提升普通账户权限、开启容器模式检测、覆盖现有同名配置、添加日志白名单或远程修改其他主机。自定义启动路径、多行命令等情况会停止并提示人工检查。

执行后点击弹窗中的“刷新启用状态”，再点击“开始只读检测”生成首份结果。点击按钮或复制命令本身不会开启检测，也不会轮换连接密钥。

普通监控账户、Windows 和 `--container-monitor` 保持原行为；安装器与客户端都拒绝在普通/兼容模式开启安全检测。安全检测不会增加 capabilities、挂载 Docker Socket、加入 docker 组、修改 sudoers 或使用 privileged 容器。缺少防火墙或 Docker 读取权限会显示未检测，不能当作安全。

NAT 客户端仍主动通过 HTTPS 上报并领取任务，不开放入站端口，不需公网 IP 或额外端口映射。容器看到的 `/proc`、网络和文件系统不一定等于容器配额，也不能据此管理宿主机。

## 本地日志白名单

没有白名单时不读取 SSH/Nginx/系统日志。由主机管理员创建 `/etc/cloudease-lite/security.json`，root 所有、0600，父目录由 root 保护：

```json
{
  "logs": [
    {"path":"/var/log/auth.log","kind":"ssh"},
    {"path":"/var/log/nginx/access.log","kind":"nginx_access"},
    {"path":"/var/log/nginx/error.log","kind":"nginx_error"},
    {"path":"/var/log/syslog","kind":"system"}
  ]
}
```

允许最多 4 个固定日志：`auth.log`、`secure`、`syslog`、`messages` 或 `/var/log/nginx/` 下受限文件名的 `.log`。拒绝路径穿越、链接与不安全父目录；日志不存在/权限不足只记录覆盖不足。安装时发现此文件且明确启用安全检测才加入 `--security-config`，也可由管理员在服务命令中明确指定。网页不能传入任意文件路径。

日志分析按需扫描，支持增量、残行续读、常见 `.1` 轮转及截断检测；单文件最多 64 KiB，窗口最多 4096 条、最长一小时。读取超限、丢失轮转文件、未知格式或缺少相应日志时标为待确认，仍可报告已观察到的异常。copytruncate 的“截断后迅速增长至旧偏移以上”、压缩旧日志、多次轮转和进程重启可能造成覆盖缺口，不能作为完整 SIEM。

支持标准 Nginx combined access 时间/状态格式、RFC3339 和常见 syslog 时间；非标准日志应先验证。默认窗口 300 秒，同来源 SSH 失败 10 次、请求 120 次、异常响应比例 40%（至少 10 个请求）、敏感路径请求 10 次；登录失败后成功和服务异常退出也产生提示。同来源可能是 NAT/代理聚合，不直接认定攻击者。只保存聚合摘要，不保存原始行、用户名或来源 IP。

## 检测依据与范围

| 维度 | 实际检查 | 边界 |
|---|---|---|
| 系统与账户 | 发行版/内核、本地更新摘要、UID 0、固定关键路径权限、sudo 提示、6 个固定程序的 SUID/SGID | 不全盘递归，不下载漏洞库；无摘要时更新状态待确认，版本号不能直接证明 CVE；sudo Include/组继承需人工核对 |
| SSH 与网络 | `sshd -T` 有效默认配置、监听地址/进程/可见 UID、UFW/nftables/iptables 规则和默认策略 | sshd 处理 Include；Match 的不同来源/用户上下文未穷举。全接口监听不代表公网暴露，云安全组和 NAT 未验证 |
| 网站与 TLS | 复用 v0.3 白名单、站点静态指令、敏感项、证书缓存、PHP 检测；最多 2 个授权站点 HEAD `/` 检查 HTTPS 跳转 | 不探测敏感文件 URL，不跟随跳转；复用并再次验证公网 IP，拒绝内网/保留地址。继承、CSP/HSTS/Frame、代理头、FPM 池与 PHP 维护状态需人工核对；宝塔仍未适配 |
| Docker | 最多 20 个容器的特权、Socket、网络、敏感挂载、CapAdd、用户、端口映射、镜像约束、根文件系统 | 只执行固定只读 ps/inspect；不为审计额外授予 Socket 权限，Docker 不可读不算通过 |
| 日志与事件 | 授权日志增量聚合、异常频率/比例与行为关联 | 阈值异常不等于攻击；有限窗口与格式，不自动封禁 |

规则参考资料：[OpenSSH sshd](https://man.openbsd.org/sshd.8)、[sshd_config](https://man.openbsd.org/sshd_config)、[Docker 安全说明](https://docs.docker.com/engine/security/)。

## 评分与风险

每个检查保留规则、维度、状态、风险等级、目标、依据、原因和建议。状态包括已检测、风险、待确认、失败、未安装、未授权；未知、失败与未授权不进入已检测分数，未安装 Docker 不扣分。没有可计分项目时显示“—”。

五个维度默认各 20 权重；在每个实际有检测结果的维度，风险项分别扣严重 60、高 30、中 15、低 5 分，单维度最低 0，再按已检测维度权重归一化至 0–100。严重风险直接令总体为严重，高风险至少令总体为高风险。每次结果和规则快照保存，分数变化可追溯。

分数只是内部规则参考，覆盖不全的 100 分不代表服务器安全。标记待处理/已确认/已处理/误报只修改处理流程，不影响检测结论与评分；原始证据和操作审计保留。

## 通知、计划与保留

- 至少支持站内通知：新严重/高风险、证书到期提示、SSH 异常、风险状态变化和扫描失败。相同事件去重，持续相同风险不会每次重复通知。
- 已读状态按用户分别存储；支持等级、时间范围及分页查询。
- 管理员可配置阈值、权重、安全数据保留 1–365 天（默认 90）、静默新通知最多 168 小时。静默不删除检测或事件，界面展示到期时间。
- 定时扫描默认关闭，可选 6–168 小时；由保存计划的用户及当前会话授权，退出、会话过期或降权后停止。不能把短会话转换为隐藏的永久管理员任务。离线/未授权客户端跳过，记录审计；授权仍在本机再次验证。
- 单机每次执行一个原有管理任务，全局同时最多 4 个安全任务；扫描截止时间 35 秒，任务租约 45 秒，结果最多 45 KiB，不阻塞 4 秒基础监控协程。安全扫描失败不影响普通监控。
- 安全数据采用独立保留策略；监控指标/事件原有 30 天和操作审计 90 天规则不变。不清空旧用户、站点或历史数据。
- Webhook 保留扩展位置，当前未实现发送，不存在任意 URL 通知或自动修复接口；不接入短信、邮件或收费服务。

## 权限与接口

安全中心只允许 admin/operator；viewer 无安全 API、报告、事件或任务结果权限。管理员可修改规则/计划，operator 可检测、复核发现及标记自己的通知已读。所有角色仍共享原工作区，不能把它当作多租户服务器隔离。

复用原有会话、Origin/CSRF、限流、审计、任务、密钥、租约和 WebSocket。任务唯一、绑定主机与密钥、一次领取、结果重试不重复执行，离线和超时显示明确状态。报告/发现必须绑定 `server_id`，不能用其他主机 ID 查询。公开前台和地图不返回安全数据。

接口为 `/api/security/overview`、`servers`、`scans`、`findings`、`events`、`alerts`、`scores`、`rules`、`reports/:id`。查看明细须传 `server_id`；扫描仅接受 `server_id`；规则只接受结构化数字参数，没有 shell、目标地址或文件路径。结果以纯文本显示，不用 HTML 注入。

## 验证与已知限制

完整测试范围见 [v0.4 验证记录](V0.4-VERIFICATION.md)。当前开发环境为 Windows，Linux 专属权限、真实 SSH Include/Match、nftables、Nginx/FPM 及不同容器下的实机行为仍须在一次性测试主机验收。不能用夹具测试宣称生产扫描、1C1G 性能或长期 CPU/内存指标已经验证。

现有安全规则为轻量审计，不能替代完整配置求值、发行版安全公告、外部可达性测试、漏洞扫描或专业日志平台；不自动修复，不停止容器，不改 SSH、防火墙、文件或 Nginx。
