# 云简 Lite v0.2 使用与升级指南

## 本次更新补充

- 监控指标和事件日志默认保留 30 天，服务端、Docker 配置与页面说明同步调整。已有部署需将 `.env` 的 `METRIC_RETENTION_DAYS` 改为 `30` 并重新启动服务；已被旧保留策略清理的数据不会自动恢复。
- 历史趋势的磁盘图例改为虚线，颜色和线型与磁盘曲线一致。

## 升级

1. 备份 SQLite 数据目录和 v0.1 发布程序；有在途任务时先等待其完成。v0.2 首次启动自动增加结构，不清空用户、会话、服务器或指标。旧账户迁移为 admin。
2. 使用 `scripts/build.ps1` 构建，或按开发指南构建控制台和 Linux / Windows 客户端。控制台、前端产物与 `bin/downloads` 应作为一组更新；Docker 源码部署使用 `docker compose up -d --build`。保留原 Compose 项目名、数据卷及 `.env` 的域名、端口和反代配置，明确将 `METRIC_RETENTION_DAYS` 更新为 `30`。
3. 启动新控制台，登录后进入设置添加 operator / viewer。v0.2 加入 roles、docker_containers、services、files、operation_logs、management_tasks 表。
4. 更新监控客户端。新客户端通过 `/api/agent/check` 认证协商后决定是否发送扩展字段，可以先升级任意一端。早期缺失时间戳的客户端仍必须升级；旧安全兼容开关仅供短期迁移。
5. 默认仍仅监控。需要 Linux 运维时，在连接密钥安装弹窗勾选「启用 v0.2 运维管理」，重新安装并输入自己的密钥；或在手工服务配置中添加 `--management`。

正常安装保留独立低权限服务账户。明确勾选运维后，Linux 安装脚本使用 root 和默认文件目录 `/opt/cloud-ease`，同时保留 ProtectSystem、ProtectHome、NoNewPrivileges、能力限制等 systemd 加固。不要在控制台容器挂载 Docker socket，也不需要开放目标机器入站管理端口。

## 客户端配置

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--management` | 关闭 | 开启 Linux 固定操作 |
| `--file-roots` / `CLOUDEASE_FILE_ROOTS` | `/opt/cloud-ease` | 逗号分隔，最多 8 个独立绝对目录 |
| `--allowed-services` / `CLOUDEASE_ALLOWED_SERVICES` | `nginx,mysql,docker,php-fpm,redis` | 最多 32 个服务名，可带 `.service` |

主机管理员可以在 `/etc/cloudease-lite/agent.env` 增加：

```ini
CLOUDEASE_FILE_ROOTS=/opt/cloud-ease,/srv/cloud-ease-data
CLOUDEASE_ALLOWED_SERVICES=nginx,mysqld,redis-server,php8.3-fpm,docker
```

允许目录及其父目录必须为 root 所有，不允许组或其他用户写入，也不能经过符号链接。例如管理员先准备 `/srv/cloud-ease-data` 并赋予 `root:root` 与 `0750`。上传需要目录可写；自动安装的 ProtectSystem=strict 仅为默认目录放开写入，新增目录时用 `systemctl edit cloud-agent` 添加：

```ini
[Service]
ReadWritePaths=/srv/cloud-ease-data
```

完成后执行 `systemctl daemon-reload` 与 `systemctl restart cloud-agent`。服务和目录白名单必须在主机修改，网页不能授予更多范围。不要配置包含不可信 bind mount 的目录；root / 挂载权限在本项目应用沙箱的信任边界之外。root 不能同时运行两个使用同一连接密钥的客户端。

## Docker

客户端使用固定路径 Docker CLI 和本机 `/var/run/docker.sock`，不继承用户指定的 Docker endpoint、context 或 CLI 插件目录。容器参数只接受 12–64 位十六进制 ID，命令通过 exec 参数数组调用；无 shell、任意参数、容器 exec 或删除功能。

页面显示 Docker 状态、版本、容器数量、镜像数量、名称、状态、端口和创建时间。最多显示 200 个容器；CLI 和日志输出最大 16 KiB，超过列表输出限制会报告数据截断，需减少主机容器数量或后续扩展分页。服务不可用或权限不足会明确显示失败。

停止与重启容器使用 5 秒 Docker 停止超时。执行动作需要 admin / operator，容器日志允许 viewer 读取。管理控制台本身也在目标 Docker 中时，停止其容器会中断控制台访问，操作由有权限的用户自行选择。

## 服务

使用 systemctl list-unit-files 和 list-units 合并开机启动与 active 状态，最多 200 个服务，白名单服务优先显示。只支持 start / stop / restart，不改变 enabled 状态。默认白名单如 README；SSH、内核、关键 systemd 服务、客户端自身服务等关键服务即使写入配置也拒绝。服务写操作需要 root；普通账户可以采集可读取的状态。

## 文件

- 只浏览已配置目录，相对路径通过 Go os.Root 绑定目录句柄；访问期间验证根目录身份。绝对路径、`..`、Windows 路径、系统或账户目录、客户端配置目录拒绝。
- 隐藏文件、常见密钥 / 凭据 / 数据库文件不展示；不显示符号链接，Linux 拒绝多硬链接和设备 / FIFO 等特殊文件。读取路径的父目录和文件也拒绝符号链接，逐级固定目录句柄并验证身份，防止通过链接绕过敏感文件名筛选。相对路径最多 32 层。
- 查看 UTF-8 文本；下载普通文件；单文件最大 32 KiB。上传仅接受 txt / md / csv / json / yaml / yml / log 的 UTF-8 文本，新文件为 0600，不覆盖、不删除、不编辑、不执行已有文件。
- 一个目录最多 1000 项，序列化元数据最多 48 KiB。文件表只缓存当前根目录最近列表的元数据，不保存内容。
- 文件内容保留在临时任务结果中 5 分钟，因此数据库和备份仍需私有权限及磁盘保护。敏感文件名筛选不是对任意内容的机密识别；主机管理员应选择只包含适合工作区用户读取的数据目录。

## 预定义命令

命令与安全页面只提供 `df -h`、`free -m`、`ip addr`、`journalctl -n 100 --no-pager --output short-iso`。admin / operator 可以确认后执行，viewer 无执行权限。每次操作 12 秒超时，输出最大 16 KiB，常见密码 / 密钥字段脱敏。没有 shell、自由输入命令、格式化或系统文件修改入口。

## 权限与审计

本版本是一个共享工作区，角色表与接口均校验角色。viewer 可以读取管理数据和自己的只读任务结果；admin 可以读取所有任务结果。operator 可以管理所有工作区服务器，但不能创建用户或修改角色。三种角色可以修改自己的密码。用户最多 100 个；不会返回密码哈希。

新增管理读取、登录和写操作均保留运维审计，包括拒绝、排队、执行、成功、失败、过期、取消。高频指标、结果轮询和日志读取不重复写审计。浏览器提交操作先入库，客户端通过匹配密钥领取；密钥轮换、退出登录、用户删除 / 角色变动会使尚未领取的操作取消。已领取操作可能已经执行，无法由注销会话撤回。

操作任务 45 秒到期，不自动重试；客户端仅重传结果。异步 202 / 轮询避免让反向代理等待慢命令。运行中的任务过期不代表未执行，刷新目标实际状态后再决定是否手动重试。返回数据 5 分钟清理、任务 24 小时删除、运维日志 90 天保留。服务器删除时保留审计历史，清理新缓存和任务；客户端仍按原流程执行匹配的卸载脚本。

日志脱敏不替代应用端的秘密管理；维护者不能假定任意日志文本中的所有凭据都可被识别。错误不返回底层系统路径、CLI 调试输出或认证密钥。控制台公网继续要求 HTTPS。

## 验收

`go test -tags nomsgpack ./...` 覆盖真实 Gin / SQLite 登录、迁移、角色、任务领取、过期、撤销、结果、数据缓存与审计；管理器测试使用注入 Runner 检查 Docker / systemd 输出及白名单 argv，文件沙箱测试实际访问隔离目录。运行 `go vet`、前端生产构建和 `tests/security-smoke.py` 验证发布程序实际主机采集。

Docker / systemd 真机动作需要在测试 Linux 主机另行验收；Windows 本地的 mock 测试与交叉编译不能代替真实 Linux 服务运行。安装脚本新增 root 运维选择也须在一次性 Linux 环境验证，不得把 fixture 脚本直接运行在生产主机。

完整本地交付记录、构建产物与真机待验收项见 [v0.2 验证记录](V0.2-VERIFICATION.md)。
