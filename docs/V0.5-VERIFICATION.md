## 失败、跳过与修正说明

- `TestNginxFailureRollsBack` 因 Windows 无创建符号链接权限跳过，未被记为通过；需要目标 Linux/有权限的隔离环境继续验证。
- 初次浏览器工具和本机界面运行时均报“failed to write kernel assets / path not found”。最终用现有 Chrome 的独立 headless 上下文完成自动化，未触碰用户的浏览器资料。
- 浏览器测试第一次在新增的离线测试节点上等待可执行状态超时；修正测试为明确选择在线模拟节点后通过，不是通过放宽产品授权使其执行。
- 原安全中心 smoke 引用了不存在的旧 `artifacts/v04-development/...` 程序，已改为标准 `bin/downloads/cloud-agent.exe` 后重跑通过。普通模式样本仍使用 v0.4 协议字段以验证兼容。
- Windows PowerShell 夹具按异常和断言判定；早期命令包装误把刻意失败用例遗留的 `$LASTEXITCODE` 当作整体失败，重新使用严格异常包装后通过。
- npm 离线依赖恢复失败、Go 模块版本查询等环境/准备错误均未写成测试通过；成功结果来自修正后的实际命令。

## 漏洞审计解释

检查日期 2026-11-04，Go 官方库 metadata 为 2026-11-02T22:01:43Z。旧 Go/x/net 扫描匹配 17 个唯一公告，12 个至少带符号路径；不等于 17 个已证明可利用漏洞。采用 Go 1.27.3、x/net 0.62.0 及必要间接更新后，只剩 [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) 的 `x/crypto` 模块级记录。`go list -deps -tags nomsgpack ./server ./agent` 未导入 OpenPGP；密码仍用 bcrypt。保留这条提示，后续依赖变化须复查，不为清零提示强行更换认证或使用未发布依赖。

npm 官方包审计报告为零；另独立检查 [Node 10 月公告](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)，Docker 构建版本和本地验证采用同一 LTS 分支 24.22.2。Go/Node 更新的目标是其官方已发布修复，没有大版本强制升级或 `audit fix --force`。
