# v0.5 实测性能记录

日期：2026-11-04。仅记录本次实际测量；没有将本地基准换算成线上容量、内存或 CPU 保证。

## 列表查询对照

环境：Windows amd64，AMD Ryzen 9 8940HX，Go 1.27.1、`nomsgpack`，同一 SQLite/GORM 依赖与 WAL/单连接设置。为隔离查询代码影响，这组前后测量在工具链安全升级之前完成；最终交付另用 Go 1.27.3 构建并回归，不能把工具链变化计入本组收益。

数据：32 个节点，每节点 900 条连续 4 秒指标，共 28,800 条（每节点约一小时）。每轮使用临时数据库，数据准备不计入计时；重复请求使数据库页缓存较热。一次操作包括服务器列表处理、最新样本读取、Gin 上下文和 JSON 序列化，不含鉴权、网络、浏览器与代理。

命令：`go test -tags nomsgpack ./server/api -run '^$' -bench '^BenchmarkV05ServerList$' -benchtime=1s -count=3`。

原始记录：`.runtime/v05-baseline/benchmark-before-clean.txt`、`.runtime/v05-benchmark-after.txt`。首次带 Gin debug 输出的试跑不作为对照，已经关闭 debug 后重新测量；不能混用那组日志。最新样本同时间排序/公开字段/两条实际 SQL 另有回归测试，GORM 构造子查询的 DryRun 不算实际执行。

这说明该规模下列表处理和分配减少；不能据此声称生产接口延迟、常驻 RSS、数据库大小或整站吞吐提升相同比例。

## 其他实际观察

| 项目 | 方法与结果 | 限制 |
| --- | --- | --- |
| Agent 实际上报 | Windows 发布程序向隔离回环 Server 连续采样，观察到 4.000、3.997 秒间隔；安全中心夹具另获得 3 条真实只读 Windows 样本 | 不是 Linux/跨公网长期计时 |
| 长输出 | Chrome 156，1440×1000，150 行模拟文本共 5,850 字符；命令容器 480px、内容 3358px，键盘/滚轮可滚动，未创建 script 节点 | 不是触屏测试或 heap profile；生产仍有 16 KiB 命令输出预算 |
| 页面切换 | Chrome 在日志/概览之间重复 3 轮，零页面脚本异常；Node 用可控 promise 验证在途合并、取消和旧响应丢弃 | 未进行小时级内存/连接压力剖析 |
| Agent 协商请求 | 代码改为一轮一次认证响应读取三个现有协议位；旧控制端协商回归通过 | 没有编造网络/CPU 百分比 |
| 生产资源包 | 新 Node 下构建成功，主 JS 约 1,101.5 kB、gzip 364.1 kB，地图独立块约 171.6 kB | 原有 500 kB 主包提示保留；不同负载下构建时长不可直接比较 |
| 清理 | 每条 DELETE 最多 500 行，过期任务事务最多 100；超过两批、取消及边界测试通过 | 没有生产长库锁等待/IO 对比数据 |

## 未测项目

启动耗时、常驻 RSS、空闲/典型负载 CPU、线上 P50/P95/P99、30 天全规模库 IO/查询耗时、真实反代慢下载、浏览器首屏、触控和长期重连 heap 均为**未测**。没有降低采样频率、缩短保留天数、清空数据或换框架来制造性能提升。
